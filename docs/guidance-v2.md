# 촬영 안내 v2 — 2026-11-11

## 목표와 구현 범위

기존의 “관측 방향과 가장 반대되는 축” 추천을 제거했다. 새 선택기는 **승인된 후보 위치·자세에서 실제로 화면 안에 들어오는 초기 근거 점에 대해, 적정 시차의 관측을 얼마나 더 얻는지** 평가한다. 후보 위치를 임의로 만들어 이동을 지시하지 않는다.

두 단계를 분리한다.

1. **보완 영역 안내:** 현재 앱·API에 적용했다. 대표 이미지의 영역 상자와 촬영 문구를 표시한다. 후보 자세가 없으면 `direction_vector=null`, `direction_asset_id=null`이며 축 화살표를 출력하지 않는다. 오래된 결과의 축 화살표도 새 앱에서 표시하지 않는다.
2. **후보 시점 선택:** [guidance.py](../poc/guidance.py)의 `select_views()`로 구현했다. 후보 위치·자세·내부 파라미터와 외부 승인 목록이 있을 때만 실행한다. 현재 앱에는 후보 자세를 생산하는 위치 추정 기능이 없어 실시간 위치 안내까지 연결한 상태는 아니다. 공개 데이터의 알려진 카메라 자세로 오프라인 실행을 검증했다.

## 입력 계약

- 초기 SfM 점의 XYZ, 재투영 오차, 관측 카메라 ID와 카메라 중심을 사용한다.
- 후보별로 ID, world-to-camera 회전·이동, 이미지 크기와 pinhole 내부 파라미터, `approved=True`가 필요하다.
- 초기 점·카메라·후보는 **동일한 SfM 좌표계**여야 한다. SfM 좌표를 현실의 중력 방향이나 미터로 해석하지 않는다.
- `posed_candidates()`는 명시한 이미지 목록과 왜곡 보정된 `PINHOLE` 또는 `SIMPLE_PINHOLE` 모델만 받는다. 왜곡 모델을 임의로 pinhole로 가정하지 않는다. 회전의 직교성·행렬식, 유한수, 초점거리·이미지 크기와 ID 중복을 검사한다.
- 승인은 외부 입력이다. 과거에 촬영된 위치라는 사실이나 SfM 등록만으로 현재 이동 가능 경로를 추정하지 않는다. 오프라인 실험의 승인은 “가용 데이터 목록에 있음”을 뜻하며 현재 현장의 안전을 보장하지 않는다.

좌표·카메라 중심·앞 방향은 [COLMAP 공식 형식](https://colmap.github.io/format.html)을 따른다. camera-local +Z가 앞쪽이며 카메라 중심은 `−Rᵀt`다.

## 제거 조건

각 후보에 대해 다음 조건을 만족하는 초기 점만 근거로 사용한다.

| 조건 | 구현 |
| --- | --- |
| 승인 | `approved`가 정확히 True인 후보만 사용 |
| 화면 가시성 | 후보 카메라 앞에 있고 실제 pinhole 투영이 이미지 안에 있음 |
| 가림 근사 | 16px 셀의 가장 가까운 점 깊이 대비 1.05배 이내. 먼 배경 점을 배제하는 희소 z-buffer |
| 관측 면 | 점→후보 방향과 기존 평균 관측 방향의 내적이 양수. 관측 반대편으로 넘어가는 후보 점 배제 |
| 거리 | 기존 관측 평균 거리의 0.5~2배. SfM 스케일에 의존하지 않는 상대 기준 |
| 시차 | 가장 가까운 기존 관측과 5~45도. 거의 같은 시점과 과도하게 다른 시점을 배제 |
| 근거 수 | 유효한 새 시차 점이 최소 5개 |

이 수치는 이번 v2 학습 비교 전에 고정한 초기 운영 기준이며 품질 데이터로 보정한 최적값은 아니다. 희소 z-buffer와 기존 평균 관측 방향은 표면·가시성의 근사다. 점군에 없는 벽·가림·장애물·미관측 공간까지 검증하지 못한다.

## 선택 기준과 중복 억제

후보 c의 점 i에 대한 가산 점수는 다음과 같다.

```text
gain(c, i) = valid(c, i) × sin(theta(c, i)) / ((1 + error_i) × (n_i + 1))
candidate_score(c) = sum_i gain(c, i)
```

- `theta`는 점에서 본 후보와 가장 가까운 기존 관측의 각도다. 새 시차가 있고 관측이 적으며 정합 오차가 작은 점에 높은 점수를 준다.
- 가장 높은 양수 점수의 후보를 하나 고른 뒤 그 후보가 관측한 점의 `n`과 가장 가까운 관측 방향을 갱신한다.
- 다음 후보는 **남은 증가량**으로 다시 평가한다. 비슷한 위치 10개를 독립 순위로 그대로 채우지 않는다.
- 유효한 후보가 부족하거나 증가량이 없으면 중단한다. 선택 수가 요청 수보다 적으면 `insufficient_candidates`를 반환하며 무작위·반대 축으로 채우지 않는다.

출력은 선택된 후보 ID, 한계 증가 점수, 근거 점 수, 실제 후보 카메라 중심과 가산 점수로 가중한 촬영 대상 중심이다. 점수는 확률·예상 PSNR·이동 거리·보장된 화질 개선율이 아니다.

## 실제 데이터와 테스트

기존 실험과 같은 공개 `room` 데이터에서 초기 A 점만 사용하고, 후보 30장 중 평가 사진을 보지 않고 10장을 선택했다. 선택 순서와 새 시차 근거 점 수는 다음과 같다. 번호는 보완 B의 프레임 번호다.

| 선택 순서 | B 프레임 | 근거 점 |
| --- | ---: | ---: |
| 1 | 39 | 4,237 |
| 2 | 15 | 2,660 |
| 3 | 37 | 2,052 |
| 4 | 10 | 1,687 |
| 5 | 23 | 1,514 |
| 6 | 19 | 1,545 |
| 7 | 5 | 1,332 |
| 8 | 35 | 258 |

근거 점 수만으로 순위를 매긴 것은 아니므로 수가 매번 감소할 필요는 없다. 합산 한계 점수는 약 180.85 → 52.32 → 26.90 → 21.55 → 18.34 → 15.35 → 13.45 → 4.96 → 4.18 → 2.80이었다. [선택 기록](../poc/data/guidance-v2/selection.json), [비교 프로토콜](../poc/data/guidance-v2/protocol.json)에 자세한 입력·설정을 보존했다.

테스트는 뒤를 향하는 카메라, 관측 반대편, 화면 밖 투영, 동일·근접 시점, 미승인 후보 제외, 희소 깊이 가림 근사, 잘못된 회전·왜곡 모델·이미지 이름, SfM 스케일·회전 불변성을 검사한다. 기존 영역·서버·실험 테스트 포함 **26개 통과**다. iOS 기기용 서명 없는 Debug 빌드도 통과했다.

## 화질 비교 상태

새 규칙과 균등 선택을 같은 초기 60장＋추가 10장, 공통 평가 10장, 3,000스텝에서 시드 42·7로 비교하도록 고정했다. **첫 학습과 재시도 모두 시스템 memory pressure=2가 30초 지속되어 자동 중단됐다.** 중단 기준과 비교 설정은 바꾸지 않았다.

따라서 현재는 v2의 화질 개선을 주장할 결과가 없다. 선택 동작·기하 조건·앱 반영 검증과 렌더링 품질 비교를 구분한다. 실패 명령·자원 로그는 `poc/data/guidance-v2/runs/coverage_gain_v2_seed42/logs/001-*`, `002-*`에 보존했다. 과거 v1 대안 비교 결과를 새 알고리즘의 결과로 재사용하지 않았다.

이 평가 10장은 이전 알고리즘 개발 중 이미 사용했다. 향후 비교가 성공하더라도 개발 데이터의 재시험이며 최종 독립 시험은 아니다. 다른 방·다른 초기 촬영·별도 평가 구간에서 추가 검증해야 한다.

자원 확보 후 다음 명령으로 실패 로그를 보존하면서 남은 비교를 재개한다. 성공 결과가 있는 run은 조건 해시를 확인하고 건너뛴다.

```sh
poc/.venv/bin/python poc/evaluate_guidance.py run --root poc/data/guidance-v2
poc/.venv/bin/python poc/evaluate_guidance.py summarize --root poc/data/guidance-v2
```

## 남은 연결 작업

실제 방향 안내에는 촬영 중 미리보기의 위치·자세를 초기 SfM 좌표에 대응시키는 기능과, 후보 위치의 이동 가능 여부를 확인하는 입력이 필요하다. 둘 중 하나라도 없으면 현재처럼 보완 영역만 안내한다. 이 재설계는 충돌 지도, AR 길 안내, 실제 기기 위치 추정을 구현하거나 검증한 것으로 취급하지 않는다.

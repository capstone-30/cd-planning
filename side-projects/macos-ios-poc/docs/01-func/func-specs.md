# 경량 PoC 기능 명세

> **사이드 프로젝트 명세:** macOS·iOS 촬영 보완 PoC의 기능과 P0/P1 기준이다. 본 프로젝트의 Ubuntu·Nerfstudio 구현 범위와 구분한다. [사이드 프로젝트 안내](../../README.md)를 따른다.

작성일: 2026-11-10 · 대상: MacBook Pro 14 M5 / 통합 메모리 16GB, iPhone 17

## 1. 목적과 완료 범위

2026-11-13 방향 조정: **복원 상태 표시와 보완 촬영 지원**을 핵심 성과로 삼는다. 정합 프레임 수는 처리 상태이며 표면 완성도나 화질 점수가 아니다. 보완 후보는 관측 근거를 확인하는 참고 정보다. 최적 시점 선택 실험은 개선 근거를 확보하지 못해 종료했으며, [중단 기록](../04-test/reports/closed-experiments.md)만 남긴다. P0/P1의 실기기 완료 기준은 유지하며, 사용자 지원 효과는 [실제 촬영 비교 절차](../04-test/capture-support-validation.md)로 검증한다.

실제 실내 촬영으로 **촬영 → Mac 업로드 → SfM 분석 → 보완 안내 → 추가 촬영 → 3DGS 전후 확인**이 연결되는지 빠르게 확인한다. 계획서 전체의 연구 타당성을 입증하는 단계는 아니다.

두 단계로 개발한다. **P0는 촬영·분석·안내까지**, **P1은 3DGS 전후 육안 비교까지**다. 경량 PoC 전체 완료는 P1까지이며, P0만 완료하면 “촬영 안내 PoC”로 표시한다. 설치와 실제 장면 처리 성공을 먼저 확인하고 앱을 연결한다.

| 구분 | 포함 |
| --- | --- |
| P0 필수 | iOS 촬영, 서버 연결, 업로드, 상태 확인, 실제 COLMAP 정합, 기존 규칙 기반 분석, 상위 3개 보완 후보, 보완 영상 업로드 |
| P1 필수 | 최초 A / 최초+보완 A+B의 3DGS 각각 생성, Mac에서 결과 열기, 비교 기록 |
| 후속 | 학습 기반 품질 예측, 여러 공간의 일반화 평가, PSNR·SSIM·LPIPS, 자동 벽·바닥 추정, 충돌·1인칭 웹 체험, iOS 내 3DGS 렌더링 |

## 2. 사용 조건

- 사용자 1명, 프로젝트 1개, 작업 1개만 처리한다. 앱은 동일 Wi-Fi의 Mac에 직접 연결한다.
- 대상은 정적인 작은 방 1개다. 사람 이동, 큰 거울·유리, 넓은 무늬 없는 벽이 많은 장면은 첫 시연에서 피한다.
- iPhone 후면 기본 카메라의 1배율로 가로 1080p/30fps SDR 영상을 촬영한다. 카메라 전환·줌을 하지 않고 천천히 움직이며 인접 시점의 겹침을 확보한다.
- 최초 A는 30~60초, 보완 B는 10~30초로 제한한다. 서버 파일 제한은 영상당 250MB다. 이 수치는 PoC 운영 설정이며 기기 성능 보장이 아니다.
- LiDAR·ARKit 없이 RGB 영상만 사용한다. 안내는 업로드 후에 제공한다.

## 3. 사용자 흐름

1. Mac에서 서버를 실행하고 표시된 접속 주소와 토큰을 앱에 입력한다.
2. 앱이 연결을 확인한 뒤 최초 영상 A를 촬영한다. 미리보기에서 재촬영하거나 업로드한다.
3. 업로드 완료 후 분석을 시작한다. 앱은 현재 단계와 경과 시간을 표시한다.
4. 완료 화면에서 등록 프레임 수와 상위 3개 보완 후보를 확인한다.
5. 후보의 대표 이미지에 표시된 영역을 보며 추가 영상 B를 촬영·업로드한다. 현재 앱에는 후보 위치·자세가 없어 방향 화살표를 표시하지 않는다. 이동 가능 여부는 직접 확인한다.
6. 서버가 A+B를 다시 분석한다. 최초 결과는 덮어쓰지 않는다.
7. P1에서 운영자가 Mac의 Brush로 A와 A+B를 순차 학습하고 결과를 연다. 최초에는 수동 실행을 허용한다.
8. 운영자가 비슷한 위치의 결과 화면을 저장하고 개선·변화 없음·악화를 기록한다. 위치 정렬이 안 되면 비교 불가로 남긴다.

## 4. 화면과 기능

| ID | 화면/기능 | 요구사항 및 통과 조건 |
| --- | --- | --- |
| F01 | 서버 연결 | 주소·토큰 입력, 연결 확인. 연결 실패와 권한 거부를 구분하고 설정 수정 후 재시도 가능 |
| F02 | 촬영·미리보기 | A/B 촬영 목적 구분, 시간 제한, 촬영 취소·재촬영. 카메라 권한 거부 시 설정 안내 |
| F03 | 업로드 | 전송률 표시. 실패 시 로컬 영상을 유지하고 재시도 가능. 서버 접수 확인 후 분석 버튼 활성화 |
| F04 | 분석 상태 | 대기/프레임 추출/SfM/영역 분석/완료/실패 표시. SfM·학습에는 근거 없는 퍼센트 표시 금지 |
| F05 | 보완 안내 | 순위, 대표 이미지와 영역 사각형, 평균 관측 수, 규칙 점수와 촬영 문구 표시. 후보 위치·자세 없이 축 방향을 생성하지 않음. 3개 미만이면 가용 영역만 표시 |
| F06 | 보완 촬영 | B를 A 프로젝트에 연결. 최초·보완 결과를 구분하고 A의 분석 결과 보존 |
| F07 | 3DGS 생성·열기 | P1. Mac에서 A와 A+B를 각각 학습·열기. 앱에는 결과 준비 여부와 운영자 기록만 표시 |
| F08 | 실험 기록 | 입력 수, 정합 수, 단계별 시간, 실패 원인, 설정, 전후 화면 및 판단을 프로젝트 폴더에 보존 |

### 보완 안내의 표현

- 사용자 문구는 **“추가 촬영 후보”**, **“규칙 기반 참고 점수”**로 한다. “예상 PSNR”, “복원 정확도”, “품질 개선 확률”로 표현하지 않는다.
- 후보 위치·자세가 없으면 대표 이미지의 보완 영역과 문구만 표시하고 방향 화살표를 생성하지 않는다.
- 자동 촬영 시점 선택과 이동 경로 추천은 제공하지 않는다.
- 5개 미만 점의 영역에는 “근거 점 부족”을 표시하고 추천 상위 3개에서 제외한다. 추천 가능한 영역이 없으면 “안내 근거 부족”으로 종료한다.
- 점군에 나타나지 않은 완전 미관측 영역은 검출하지 못한다. 점수 하락만으로 복원 품질 개선을 판정하지 않는다.

## 5. 실패 시 동작

| 상황 | 동작 |
| --- | --- |
| 서버 미접속/로컬 네트워크 권한 거부 | 서버 주소·동일 Wi-Fi·권한 확인 안내, 촬영 파일 유지 |
| 파일 과대/지원하지 않는 영상/디코딩 실패 | 분석 시작 전 거절하고 짧게 다시 촬영하도록 안내 |
| 유효 프레임 부족 | “천천히, 겹치는 시점으로 다시 촬영” 안내 |
| 정합 부족/여러 개의 분리된 모델 | 기준을 충족하는 단일 모델이 없으면 분석 실패. 공간이 복원된 것으로 표시하지 않음 |
| 분석·학습 시간 초과/메모리 압박 | 해당 프로세스 중지, 실패 단계·로그 보존. 더 작은 설정으로 수동 재시도 |
| 앱 종료/서버 재시작 | 앱은 저장한 프로젝트 ID로 상태 재조회. 서버 재시작 시 중단된 작업은 실패 처리하며 자동 재개하지 않음 |
| B가 A와 연결되지 않음 | 보완 정합 실패 표시. 별도 장면을 합쳐 전후 결과로 제시하지 않음 |

## 6. 완료 판정

### P0: 실제 촬영 안내

- iPhone 실기기에서 A 업로드 → 실제 COLMAP 정합 → 대표 이미지가 있는 보완 후보 확인까지 성공한다.
- 입력 프레임의 60% 이상, 최소 30장이 하나의 SfM 모델에 등록되고 희소 점이 100개 이상이다. 이는 초기 운영 기준이며 복원 품질의 보증 기준은 아니다.
- 안내를 보고 B를 촬영하고 A+B 분석 결과를 별도로 확인한다.
- 네트워크 단절·정합 실패·재업로드를 각각 한 번 확인한다.
- 업로드 제외 A 분석 **10분 이내를 목표**로 측정한다. 초과 시 실패 원인과 실제 시간을 기록하고 프레임 축소 여부를 판단한다.

### P1: 3DGS까지 연결

- 실제 A와 A+B에서 생성한 3DGS 두 개가 Mac에서 열린다. 합성 데이터나 미리 만든 외부 장면은 통과 근거로 사용하지 않는다.
- 각 학습은 **15분 이내를 초기 목표**로 하되 실측 전 성능을 약속하지 않는다. 같은 해상도·학습 스텝·밀도 설정을 사용한다.
- 좌표 정렬 가능한 경우 대응 화면 최소 3개와 육안 판단을 남긴다. 정렬 불가면 생성 성공과 비교 실패를 분리 기록한다.
- 결과가 악화되어도 연결 검증은 성공일 수 있다. “보완 안내의 효과 입증”과 구분한다.

## 7. 범위 선택의 이유

기존 `poc/poc.py`의 규칙 기준선을 재사용한다. iOS는 촬영과 안내 확인에 집중하고, Mac의 Brush 뷰어로 3DGS 생성 여부를 확인한다. 학습 모델과 별도 웹 뷰어 없이 가장 먼저 실제 데이터 파이프라인의 성립 여부를 판단한다.

UX/UI 상세는 [uxui-specs.md](../02-uxui/uxui-specs.md), 기술 구조·데이터 형식·실행 순서는 [tech-specs.md](../03-tech/tech-specs.md)를 따른다.

# iOS·Mac PoC 기능

대상: MacBook Pro 14 M5·16GB / iPhone 17. Ubuntu 본 프로젝트와 별개다.
**P0는 촬영 안내, P1은 3DGS 전후 확인까지**이며 전체 완료는 P1 기준이다. [현재 판정](../../../common/docs/validation.md)은 실기기 P0/P1 미완료다.

## 조건·흐름

사용자·프로젝트·작업 각 1개, 동일 Wi-Fi의 Mac과 정적인 작은 방을 기준으로 한다. 사람 이동·큰 거울·유리·무늬 없는 벽이 많은 장면은 피한다. RGB만 사용하며 LiDAR·ARKit은 쓰지 않는다.

후면 기본 카메라 1배율·가로 1080p/30fps SDR, 줌·렌즈 전환 없이 천천히 겹치게 촬영한다. 최초 A 30~60초, 보완 B 10~30초, 파일당 250MB다. 2fps에서 유효 후보 30장을 확보하려면 B는 15초 이상 필요하다.

연결 → A 촬영·미리보기·업로드 → 분석·안내 → B 촬영·업로드 → A+B 별도 분석 → Mac에서 동일 설정으로 두 3DGS 학습·열기·비교.

| ID | 기능·통과 조건 |
| --- | --- |
| F01 | 주소·토큰 연결, 연결 실패·권한 거부 구분 및 재시도 |
| F02 | A/B 촬영·시간 제한·취소·재촬영, 카메라 권한 안내 |
| F03 | 업로드 전송률, 실패 시 원본 보존·재전송, 접수 후 분석 활성화 |
| F04 | 대기·전처리·SfM·분석·완료·실패와 경과 시간. SfM·학습의 추정 퍼센트 금지 |
| F05 | 근거 점 5개 이상인 상위 최대 3개 영역의 대표 이미지·상자·관측 수·규칙 점수·문구 |
| F06 | 같은 프로젝트의 A+B 연결, A 결과 보존 |
| F07 | P1: 두 3DGS를 Mac에서 학습·열기, 앱에는 준비 상태·운영자 기록 |
| F08 | 입력·정합 수, 설정·시간·실패·로그·전후 화면 보존 |

안내는 “추가 촬영 후보”, 점수는 “규칙 기반 참고 점수”다. 정합 수·점수를 화질·완성도·개선 확률로 표시하지 않는다. 완전 미관측 영역·최적 시점·이동 경로는 추정하지 않으며 후보 자세 없이 화살표를 만들지 않는다. 후보가 없으면 “안내 근거 부족”으로 표시한다.

## 실패·완료 판정

- 연결·권한·업로드 실패 시 로컬 영상을 보존한다. 잘못된 영상·과대 파일은 분석 전에 거절한다.
- 유효 프레임·단일 모델 정합 부족은 실패로 표시하고 천천히 겹치게 재촬영하도록 안내한다. B가 A와 연결되지 않으면 합쳐 제시하지 않는다.
- 시간 초과·메모리 압박은 중지·로그 보존 후 축소 설정으로 수동 재시도한다. 앱은 저장 ID로 복구하고 서버 재시작 작업은 실패 처리한다.
- **P0:** 실제 iPhone A 업로드·COLMAP·안내·B·A+B 확인, 네트워크 단절·정합 실패·재업로드 각 1회 확인. 단일 모델에 입력 ≥60%·30장·100점, A+B는 A ≥60%·B ≥10장. A 분석은 업로드 제외 10분 목표로 실측한다.
- **P1:** 실제 A/A+B를 같은 해상도·스텝·밀도로 학습하고 Mac에서 연다(각 15분 목표). 정렬 가능하면 대응 화면 ≥3쌍·육안 판단을 보존한다. 정렬 불가면 생성 성공과 비교 실패를 분리한다.

목표 시간은 성능 보장이 아니다. 합성·외부 장면으로 실기기 통과를 대체하지 않으며 결과 악화도 그대로 기록한다. 연결 성공은 안내 효과 입증이 아니다.

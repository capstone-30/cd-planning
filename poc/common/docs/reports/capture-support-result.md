# 복원 상태·보완 촬영 지원 점검 — 2026-11-13

**판정: 저장된 Windows 실측 자료의 상태 보고와 후보 참조는 점검을 통과했다. 실제 사용자의 보완 촬영 지원 효과는 미측정이다.**

후속 [보완 이미지 추가 효과 PoC](supplement-effect-result.md)는 같은 평가 사진으로 A/A+10을 새로 학습해 두 시드 모두 품질 개선을 확인했다. 저장된 실사 사진의 오프라인 시험이며, 아래 실제 사용자 촬영 시험의 대체 결과는 아니다.

제품 목표를 복원 상태 표시와 보완 촬영 지원으로 조정했다. v2 시점 선택의 우수성은 완료 조건에서 제외했다. 현재 앱은 이미 정합 수·대표 이미지·규칙 참고 점수·한계를 표시하므로 이번에는 앱이나 선택 알고리즘을 바꾸지 않고 증거와 평가 절차를 정비했다.

## 실행한 검증

`check_capture_support.py`가 `data/core-check/summary.json`의 project/run ID를 따라 Windows 최초·보완 모델을 읽었다. 로컬에 함께 남아 있는 과거 Mac run을 섞지 않았다. 원본 실측 파일을 수정하지 않고 [검사 결과와 입력 SHA256](capture-support-check.json)을 별도 저장했다.

| 항목 | 최초 A | A+B |
| --- | ---: | ---: |
| 선택 입력 프레임 | 60 | 100 |
| 모델 등록 프레임 | 40 | 100 |
| 등록 비율 | 66.7% | 100% |
| 희소 점 | 7,581 | 24,783 |
| 참고 후보 | 3 | 3 |

- 초기 미정합 20장(초기 캡처의 000001~000020.jpg)이 A+B에서 모두 등록됐다. 초기 등록 40장의 손실은 0장, 보완 프레임은 40장 등록됐다. 서로 다른 모델의 이미지 ID가 아니라 **캡처 경로를 포함한 이미지 이름**으로 비교했다.
- 보고서 입력·등록 수와 모델이 일치했고 영역별 점 수 합계도 모델의 점 수와 일치했다.
- 후보 6개 모두 근거 점 5개 이상, 등록된 대표 이미지 참조, 유효한 정규화 상자, 존재하는 PNG 파일 참조를 확인했다. 후보 순위와 방향 화살표 미제공도 확인했다.
- 자동 테스트 29개 통과. 새 테스트는 등록 회복과 동시에 기존 등록 손실이 생기는 경우, 알 수 없는 초기 프레임 거부를 검사한다.

이 점검은 새 SfM/Brush 실행이 아니다. 후보 상자가 의미상 올바른 물체를 가리키는지, PNG 전체 디코딩·화면 렌더링, 사용자가 영역을 찾을 수 있는지는 검사하지 않았다. 등록률 100%를 공간 완성도 100%로 해석할 수 없고, 점 수 증가를 화질 개선이나 안내 효과로 해석할 수 없다. B는 안내에 따라 촬영한 영상이 아니며 자유 촬영 대조군도 없다.

## 다음 실험 준비

사용자가 실제 촬영 영상이 아직 없음을 확인했다. [실제 촬영 비교 절차와 기록 양식](../capture-support-validation.md)을 준비했다. 장면 3개의 파일럿에서 동일 A·동일 20초 보완 예산으로 안내/자유 촬영을 분리하고, 보완 전에 고정한 ROI와 평가 시점으로 비교한다. 상태 이해·영역 찾기·촬영 수행 여부를 먼저 기록하며 육안 변화는 별도 결과로 남긴다.

현재 종료 상태는 **저장 자료 점검 완료 / 실제 촬영 자료 대기**다. 실기기 P0/P1과 실제 지원 효과는 완료로 처리하지 않았다.

## 재현

공용 PoC 루트(`poc/common/`)에서 실행한다. 출력은 새 파일이어야 하며 기존 증거를 덮어쓰지 않는다. Python의 assert 검사를 사용하므로 `-O` 옵션 없이 실행한다.

```sh
python3 check_capture_support.py --output /tmp/capture-support-check-new.json
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

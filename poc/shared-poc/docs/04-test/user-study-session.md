# 안내 촬영 vs 자유 촬영 — 파일럿 실행표

준비일: 2026-11-13 (한국 시간). 상태: **촬영 전 / 실제 사용자 효과 미측정**.

사용자가 촬영 전임을 확인했다. 현재 `poc/data/core-check/A.mov`, `B.mov`는 공개 Mip-NeRF 360 사진을 이어 붙인 영상이다(`poc/run_core_check.py`). 사용자 촬영 대조군으로 사용하지 않는다.

## 이번 실행의 고정 조건

직전 논의에 따라 **동일한 초기 60장에 추가 10장을 넣었을 때, 영역 표시 안내가 자유 촬영보다 품질을 더 개선하는가**를 비교한다. 기존 [검증 계획](capture-support-validation.md)의 추가 최대 40장 절차와 구별되는 60+10 파일럿이다. 결과를 확인한 뒤 예산을 바꾸지 않는다.

| 항목 | 이번 실행 |
| --- | --- |
| 장면·참여자 | 정적 실내 장면 3개, 장면별 서로 다른 초보자 2명, 총 6명. 각 참여자는 한 조건만 수행 |
| 배정 | 두 사람의 ID를 먼저 기록하고 동전으로 한 사람을 안내/자유에 배정. 나머지는 반대 조건. 배정 결과를 촬영 전 기록 |
| 초기 A | 장면마다 운영자가 30초 촬영, 2fps에서 균등 선택한 60장. 두 조건에 같은 원본 A 사용 |
| 안내 | A 분석에서 생성된 영역 상자가 있는 대표 사진 최대 3개 |
| 자유 | 안내 조건과 동일한 대표 사진, 같은 순서, 상자만 없음 |
| 공통 설명·열람 | 아래 공통 문구, 대표 사진 열람 60초. 같은 등록 수·한계 설명 제공. 규칙 점수는 양쪽 모두 숨김 |
| 보완 B | 각 20초, 2fps 후보에서 동일 규칙으로 균등 선택한 10장. 촬영 시간은 공통 제한이며 효율 우위를 별도로 주장하지 않음 |
| 복원 | A / A+B-guide / A+B-free, 긴 변 960, Brush 3,000스텝·최대 30만 splat·시드 42와 7. 실제 버전과 명령 보존 |
| 주 평가 | 사전 고정한 ROI와 평가 시점에서 A 대비 누락·끊김·번짐의 개선/동일/악화/판정 불가 |
| 보조 평가 | 안내 이해 여부, 대상 찾기 여부·시간, 선택·등록 프레임, 처리 실패, 학습 시간 |

시드 2개는 학습 변동 확인이며 참여자 2명으로 세지 않는다. 장면·ROI·시드별 결과를 독립 표본으로 부풀리지 않는다. 장면 3개는 탐색 파일럿이며 통계적 우위나 일반화를 판정하지 않는다.

## 현장 순서

1. 장면의 물체·조명·카메라 설정을 고정한다. 후면 기본 카메라 1배율, 가로 1080p/30fps SDR로 A를 30초 촬영한다. 개인정보가 포함되지 않는 장면을 사용하고 참여자 동의 여부를 기록한다.
2. A 분석을 완료하고 60장 선택 여부를 확인한다. 실패하면 실패 원인을 기록하고 해당 장면의 비교를 시작하지 않는다. 후보가 없으면 안내 불가로 기록한다.
3. 운영자가 A 렌더에서 평가할 실제 영역 최대 3개와 공통 평가 시점 3개를 정한다. ROI·A 화면·시점·후보와 ROI의 대응 여부를 보완 촬영 전에 저장한다. 후보에 맞는 ROI만 사후 선택하지 않는다. 완전 미관측 영역의 수동 지정 여부도 기록한다.
4. 안내용 이미지는 A run의 `analysis/report.json` 및 `assets.json`으로 찾는다. 자유용 이미지는 각 후보의 `representative_image`에 해당하는 **같은 A run의 `frames/` 원본**을 쓴다. 양쪽 표시 크기·사진 순서를 맞춘다. 자유 조건에 평가 ROI나 대상 이름을 알려주지 않는다.
5. 참여자를 배정하고 아래 설명을 읽는다. 60초 열람 후 같은 시작 위치에서 각 20초 보완 촬영한다. 상대방의 촬영·안내 화면·처리 결과를 보지 않게 한다. 운영자가 특정 위치를 추가로 지시하면 개입 내용을 기록한다.
6. 같은 A 원본을 사용해 두 combined run을 분리한다. 한 프로젝트에 A, B-guide, B-free를 별도 capture로 업로드하고 combined 요청에는 A와 해당 B만 넣는다. A의 capture ID와 원본 SHA256을 보존한다. 앱의 일반 보완 화면에는 두 조건을 통제하는 기능이 없으므로 이번 파일럿은 운영자가 사진을 별도로 제시하고 API로 조건별 run을 만든다.
7. 각 run의 선택 프레임과 설정을 확인한 뒤 동일 설정으로 순차 학습한다. B 10장 모두가 정합돼야 현재 combined 성공 기준을 충족한다. 실패를 숨기거나 성공할 때까지 B를 다시 골라 넣지 않는다. 분석 가능한 결과의 품질과 전체 시도의 실패율을 함께 보고한다.
8. 공통 A 카메라로 정렬하고 상대 RMSE 0.1 기준을 적용한다. 정렬 또는 같은 시점 재현에 실패하면 판정 불가다. 근사 시점 화면으로 품질 우위를 판정하지 않는다.
9. 운영자가 조건을 숨긴 X/Y 화면을 만들고 별도 대응표를 보관한다. 평가자 2명이 독립 평가한 뒤 조건을 공개한다. 불일치는 원문 그대로 남긴다. 독립 평가 영상은 학습에서 제외하고, 자세·노출·픽셀 정렬 검증 전에는 PSNR/SSIM을 계산하지 않는다.

## 읽어 줄 문구

공통: “현재 복원 상태와 대표 사진을 확인해 주세요. 등록된 사진 수는 공간의 완성도를 뜻하지 않습니다. 60초 동안 확인한 뒤, 복원에 도움이 된다고 생각하는 부분을 20초 동안 촬영해 주세요. 천천히 옆으로 이동하며 화면이 겹치도록 촬영해 주세요.”

안내 조건 추가: “사진의 주황 상자는 관측 근거로 제시한 보완 후보입니다. 이 영역을 참고해 촬영할 부분을 정해 주세요. 화질이 반드시 나쁘거나 촬영 후 반드시 개선된다는 뜻은 아닙니다.”

자유 조건에는 추가 문구 없이 표시 없는 같은 사진을 제시한다. 현재 앱의 후보별 촬영 문구를 안내 조건에만 추가로 읽어 주지 않는다. 이 비교에서 조작하는 것은 영역 표시와 그 의미 설명이다.

## 실행 설정

[기존 실행 안내](../../../macos/docs/05-ops/runbook.md)의 서버 실행에 아래 인수를 사용한다. 토큰은 기존 절차대로 환경 변수에만 설정한다. 기존 데이터와 분리된 새 경로를 사용한다.

```sh
cd poc/shared-poc/poc
.venv/bin/python -m server --host 127.0.0.1 --port 8080 \
  --data data/user-study-60plus10 \
  --initial-frames 60 --supplement-frames 10 --long-edge 960 --blur-threshold 0
```

실기기 업로드 시 `--host`는 Mac의 실제 LAN 주소로 바꾼다. 20초 B는 2fps에서 약 40장의 전처리 후보를 확보한다. 현재 파이프라인은 역할별 유효 후보가 최소 30장이어야 하므로 5초 영상으로 10장만 확보하는 방식은 사용하지 않는다. 최종 B 선택 수는 별개로 10장이다. 선명도 임계값은 0으로 고정하며 결과를 본 뒤 변경하지 않는다.

현재 PATH에 FFmpeg·FFprobe·COLMAP은 확인됐지만 Brush 명령은 없었다. 학습 전에 로컬 Brush 실행 파일과 해당 버전의 옵션을 확인해야 한다. 이 실행표 작성은 SfM·학습 또는 실기기 동작 검증 결과가 아니다.

## 진행 여부를 좌우하는 항목

### 1. 실제 SfM·3DGS 성공이 아직 없다

현재 통과한 연결 테스트는 외부 명령을 fixture로 대체한다. 실제 특징 매칭, 작은 방의 카메라 복원, Brush 입력 호환성, 학습 메모리·시간은 확인하지 않는다. P0와 P1 모두 완료 판정할 수 없다.

기술 선택 자체에는 실행 경로가 있다. [COLMAP 공식 설치 안내](https://colmap.github.io/install.html)는 macOS Homebrew 설치를 안내하고, [Brush 공식 저장소](https://github.com/ArthurBrussee/brush)는 macOS·COLMAP 입력·학습·PLY 뷰어·CLI를 지원한다고 명시한다. 이는 M5 16GB에서 이 프로젝트 설정이 성공한다는 성능 보장은 아니다. [원본 Graphdeco 구현](https://github.com/graphdeco-inria/gaussian-splatting)은 CUDA를 요구하므로 Mac 네이티브 학습 경로로 그대로 사용할 수 없다.

**다음 행동:** 실제 방 A 영상으로 960px·30~60프레임부터 SfM과 Brush를 순차 실행한다. 설치 버전, 희소 모델, PLY 열기, 시간·memory pressure·swap을 기록한다. 로컬 학습이 실패하면 입력을 축소해 재시험하고, 그래도 실패하면 계획서의 GPU 서버 경로 확보 또는 범위 축소를 결정한다.

### 2. 현재 점수는 복원 품질 예측을 검증하지 않는다

`poc.py`의 점수는 관측 수·방향 다양성·재투영 오차에 정한 가중치를 적용한다. 합성 데모는 관측을 인위적으로 추가하므로 점수 감소가 실제 렌더링 개선의 증거가 될 수 없다. 점이 생성되지 않은 완전 미관측 공간도 분석 대상에 들어오지 않는다. 선명도는 서버의 프레임 필터·기록에 사용하며 점수 입력에는 포함되지 않는다.

계획서의 주요 연구 가설인 “촬영 특징으로 새로운 공간의 렌더링 품질을 예측한다”는 별도 검증이 필요하다. 현재는 학습 모델, 영역별 정답 데이터, 독립 평가 시점 렌더링·오차 산출이 구현되어 있지 않다. 영역별 정답을 얻으려면 오차 이미지의 픽셀을 대응 3D 영역에 귀속시키는 깊이·가시성·마스크 기준도 정의해야 한다.

**다음 행동:** 처음에는 한 공간의 촬영 부족 조건 몇 개로 특징과 독립 평가 영상의 오차를 연결할 수 있는지 확인한다. 이후 공간 단위로 분리한 데이터에서 관측 수만 사용하는 기준선과 비교한다. 한 공간의 여러 영역을 학습·시험에 무작위 분배해 새로운 공간 성능으로 보고하지 않는다. 영역 대응이 불안정하면 계획서의 대안대로 공간 전체 단위 예측으로 축소한다.

### 3. 방향 추천은 실제 촬영 후보로 사용하기 전에 보완해야 한다

`poc.py:102`의 규칙은 여섯 축 중 기존 관측 방향과 가장 덜 겹치는 축을 고른다. 표면을 원점, 카메라를 `(2,0,0)`, `(3,0,0)`에 놓고 근거 점 5개를 입력하면 `-X`를 추천한다. 표면이 방의 벽이고 실내가 `x>0`이라면 그 후보는 벽 뒤일 수 있다. 이는 합성 반례이며 실제 장면 실패를 측정한 결과는 아니다.

**다음 행동:** 초기 실험은 운영자가 가시성과 접근 가능성을 확인한 후보만 촬영한다. 제품의 자동 이동 안내를 주장하려면 같은 표면을 볼 수 있는지와 이동 가능 영역을 함께 검사해야 한다. 최소 범위에서는 수동 후보 위치를 정하고 기존 시점보다 다른 관측을 제공하는 후보를 고르는 방식부터 검증한다. 방향 문구만 바꾸거나 점수 가중치만 조정해서 해결되는 문제는 아니다.

### 4. A와 A+B의 육안 비교만으로 안내 효과를 입증할 수 없다

추가 프레임 수가 늘어난 효과와 추천 위치의 효과를 분리해야 한다. 현재 운영자 도구는 두 결과의 정렬과 화면 기록을 지원하지만 독립 평가 시점의 정량 비교를 수행하지 않는다. 같은 영역 ID도 재실행 후 같은 실제 영역을 뜻하지 않는다.

**다음 행동:** 최초 A와 학습에 사용하지 않는 평가 영상 E를 고정하고, 같은 추가 프레임 수·같은 학습 설정으로 안내 촬영과 무작위 또는 단순 촬영 기준선을 비교한다. 단순 무작위 프레임 분할보다 분리된 평가 촬영 구간을 사용하고, 평가 카메라를 복원 좌표계에 대응시키는 절차를 고정한다. 좌표 정렬·비교가 불가능한 실험은 실패 또는 비교 불가로 남긴다.

### 5. 계획서 전체 범위는 현재 PoC보다 크다

웹 1인칭 뷰어, 바닥·벽 추정, 충돌 처리와 스케일 보정은 현재 구현에서 확인되지 않았다. 희소 점군으로 질감 없는 벽·바닥의 경계를 자동 복원할 수 있는지도 별도 위험이다. 학습 모델 여러 종류, 자동 평면, 웹 체험을 동시에 확장하면 핵심 가설 검증이 늦어진다.

**다음 행동:** 실제 복원과 평가 데이터 생성이 성공할 때까지 새 UI·모델 비교·자동 충돌 기능 확장을 보류하는 편이 합리적이다. 이후 웹 뷰어와 수동 이동 경계부터 연결하고 자동 평면은 별도 실험으로 추가한다.
